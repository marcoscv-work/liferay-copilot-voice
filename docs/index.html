Why Copilot Voice

Content creation that doesn't need your hands — or your eyes

Born as an accessibility exploration, grown into a full authoring flow: everything the copilot shows on screen is also spoken through screen-reader live regions, and everything it asks can be answered by voice.

Voice-first flows

Web content, blog entries, document uploads and custom Objects — driven end to end by natural phrases, with dictation, inline punctuation and voice navigation between fields.

Native to Liferay

Ships as a custom element client extension. Same-origin calls with the user's session and CSRF token, portal language via ThemeDisplay, permissions enforced by Liferay itself.

Three languages, all layers

Spanish, English and Italian — not just labels: voice command phrases, dictation locale and every screen-reader announcement are translated. Adding a language is two files.

Dynamic Object flows

Point it at your CMS content structures and it builds a guided voice flow for every field type — picklists, booleans, numbers, dates — with no code changes.

Format review

A deterministic pass fixes capitalisation, commas and question wrapping before publishing — or plug in an LLM endpoint for full writing assistance. Either way, you approve the result.

Accessible by design

Every state change is mirrored to ARIA live regions with composed prompts (question → options → actions). A blind user hears exactly what a sighted user sees.

How it works

From silence to published in four steps

Activate

Press SPACE (configurable). The mic morphs into live voice bars — you're listening.

Say what you want

"Crear contenido", "new blog", "subir archivo", "crea spazio"… the bars flash purple when a command lands.

Dictate

Pick a space, dictate title and body — or type, both always work. Say "revisar formato" for a cleanup pass.

Publish

Say "enviar". The entry is created in Liferay through the same headless APIs the portal uses.

Everything is a command — or a click

The side panel mirrors what you can say at every moment. Every pill is also clickable, dictation fields are real inputs you can type into, and pressing the activation key mid-flow asks before cancelling. Voice never locks you in.

Dynamic flows

Your content structures become voice flows

Define a content structure in Liferay CMS — a press note, a product sheet, an event — and the copilot discovers it at startup and builds the whole guided conversation for it.

Every field type, handled

  • Text / RichText — dictation fields with append-on-pause and voice navigation.
  • Picklist / Boolean — option cards you can say or click.
  • Numbers — digits or number words, integer and decimal aware.
  • Date / DateTime — say a full date ("May 15th 2025", "mañana") or build it part by part: day… month… year.
  • Required fields — validated before submit; the flow jumps back to whatever is missing.

No admin setup beyond the CMS itself

Structures live where they always did — the CMS content structures library. The copilot reads their definitions through the headless Object API, fetches picklist values, and uses your field labels as spoken prompts. Rename a field in Liferay and the voice prompt follows.

Install

One zip, zero configuration

Copilot Voice is a custom element client extension: static files served by your own portal. No extra servers, no credentials, no CORS.

1 · Build the deployable zip

The repo ships the official Liferay Workspace tooling — one command produces the artifact:

git clone https://github.com/marcoscv-work/liferay-copilot-voice
cd liferay-copilot-voice
npm install
npm run build:cx
# → dist/liferay-copilot-voice-deployable.zip

2 · Deploy it

Self-hosted: drop it in the bundle's deploy/ dir (or let the build do it). Liferay SaaS/PaaS: upload it from the cloud console.

LIFERAY_HOME=/path/to/bundle npm run build:cx
# hot-deploys straight into $LIFERAY_HOME/deploy

3 · Place the widget

Add the Liferay Copilot Voice widget (category Client Extensions) to a blank, full-width page. That's it — users open the page, grant the mic once, press SPACE and talk.

  • Auth: the logged-in user's session — permissions enforced by Liferay.
  • Language: follows the user's portal language.
  • No content spaces yet? The copilot offers to create the first one.

What you need

  • Liferay 2026.Q3 or newer (SaaS, PaaS or self-hosted) — the copilot builds on the Liferay CMS APIs (content spaces), GA since 2026.Q3. On 2026.Q1/Q2 it works with the Liferay CMS feature flags enabled (LPD-17564 and dependencies). Check the Marketplace listing for the exact tested releases.
  • A browser with speech recognition (the Web Speech API) — Chrome, Edge and Safari all work today; Firefox doesn't ship it yet.
  • A microphone — the browser asks once per site.
  • Nothing else: no extra servers, no API keys, no per-user setup.

Want to hack on the copilot itself? The README covers the development setup.

Configure

Small config, sensible defaults

Everything tunable lives in config.json. Commands and flow structure live in flows.<lang>.json — new phrases don't need code.

config.json

{
  "activationKey": { "code": "Space", "label": "SPACE" },
  "locales":  { "es": "es-ES", "en": "en-US", "it": "it-IT" },
  "speech":   { "provider": "web-speech" },
  "assist":   { "provider": "none" },
  "submit":   { "askFormatReview": false }
}

What each knob does

  • activationKey — any KeyboardEvent.code: Space, KeyF, AltLeft…
  • locales — UI language → BCP-47 tag for speech recognition.
  • speech.provider — a clean seam: swap the browser recogniser for Deepgram, Whisper & co. by registering one factory.
  • assist — optional LLM writing review; point endpoint at your own service. Falls back to the built-in deterministic format pass, so it can never block publishing.
  • askFormatReview — ask "review formatting?" before every submit.
Languages

Add a language in an afternoon

Each locale is two data files — no engine code. Italian was added exactly this way and ships as the reference.

FileWhat you translate
language/Language_xx.propertiesEvery UI string — including the announce* block that screen readers speak aloud.
flows.xx.jsonVoice command phrases, aliases, step labels and spoken prompts for every flow.
src/08-boot.jsAdd the code to SUPPORTED_LOCALES; map it in config.json locales.
markup.jsOne <button data-lang="xx"> in the dev language toggle.

Inside the portal the language is chosen for you: the copilot reads Liferay.ThemeDisplay, so an es-MX user dictates in es-MX and an unsupported portal language falls back gracefully.

In practice

What people do with it

The dictated blog post

"Crear blog" → dictate the title, the body with spoken punctuation, say "añadir imagen" and pick a cover by number — "imagen dos" — then "revisar formato" and "enviar". Never touched the keyboard.

The structured press note

A "Press note" content structure with status picklist, embargo date and priority number becomes a guided interview: the copilot asks for each field in order and validates the required ones.

The screen-reader session

With VoiceOver or NVDA running, every prompt, option list and confirmation is announced. The whole authoring flow — spaces, fields, review modal — works ears-and-voice only.
